# osoe 0.1.0

The first release of osoe, an implementation of OpenSHMEM 1.6 over TCP and
io_uring on Linux, for clusters of ordinary Ethernet. The README says what it is
and how to use it; this note says what was checked before the tag, and what it
leaves for later.

## What it is

- **OpenSHMEM 1.6 for C, complete**: every routine of the specification's C
  interface, the deprecated ones of its Annex F among them; contexts and
  `SHMEM_THREAD_MULTIPLE` through `shmem_init_thread`; teams; the 1.6 scans and
  active sets smaller than the job.
- **Between nodes over TCP with io_uring, within a node through shared memory**,
  started by Slurm's `srun` or by its own launcher, with no PMI library.
- **Built from the distribution's own packages**: Linux 6.7 or newer, liburing
  2.6 or newer, CMake 3.25 or newer, GCC or Clang. With it: `oshcc`,
  `osoe-launch`, `osoe-stat`, `osoe-pacer`, `osoe-bench` and `probe`.
- **Licensed** under the GNU Lesser General Public License, version 3 or any
  later version.

## Known limits

Nothing the Pi cluster measured falls short of the floor's pins: its round trips
are 9 to 10% above an io_uring echo's, its streams at line rate. The README's
Limits list every limit a program can meet; in short:

- **Tested on aarch64 only.** x86-64 built and ran under emulation, without an
  x86-64 kernel; every node of a job must have the same architecture.
- **TCP only**, no RDMA backend; one thread a node moves every message between
  nodes.
- **Teams**: a PE in at most `OSOE_MAX_TEAMS` teams at once (256 by default), a
  node holding at most `OSOE_TEAM_BLOCKS` (1,024).
- **Scale**: at most 1,025 nodes at the default connection budget, every pair
  of nodes connected at start-up; 65,535 PEs a node.
- **Memory**: one symmetric heap a PE, its size fixed at start-up, in
  `/dev/shm`; global and static variables symmetric only in a program linked by
  `oshcc`.
- **Threads**: `shmem_init` provides `SHMEM_THREAD_SERIALIZED`;
  `SHMEM_THREAD_MULTIPLE` comes through `shmem_init_thread`.
- **Failures**: a PE or a node that dies ends the whole job, as does a process
  that leaves without `shmem_finalize`; a collective the PEs of one node call
  differently is not detected.
- **C only**: no Fortran bindings; MPI in the same program has not been tried;
  `shmemx.h` is empty.
- **Slurm**: run with `--cpu-bind=none`; a login that ends on a node just before
  a job starts there can stall its start (systemd-logind's `RemoveIPC`).

What the reviews left for after this release is on `docs/release-checklist.md`'s
"After the release".
