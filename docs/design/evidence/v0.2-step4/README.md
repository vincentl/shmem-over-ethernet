# v0.2 step 4's evidence

Raw outputs of v0.2's fourth step, the progress helpers
(`docs/prompts/done/v0.2-step4-progress-helpers-prompt.md`; the design is
`docs/design/progress-helpers-proposal.md`), one directory per session. The
directories hold Parts 0 to 3 of it: Part 0, the profile of the one thread and
the ladder that followed from it - a put fills the room an open buffer has, the
kernel's unsent queue limited by the link, a default buffer of 256 KiB, the
receive parsed in place, and the zero-copy send behind a setting; Part 1, the
owners; Part 2, the control wire; and Part 3, the helper threads - and the
exploration of question 4, a blocking get a piece at a time. A session on the
Pi cluster ran on its four nodes at a gigabit (`docs/pi-cluster.md`), the
others in the development VMs, over loopback unless a line says otherwise. The
Pi's numbers are read from here into `docs/pi-cluster-results.md`, "v0.2 step
4". Read a directory from its record, in the second column, which cites the
files a claim rests on. A script writes the repository's directory as `<repo>`;
it records what ran and is not one to run as written
(`docs/decisions/README.md`, "The tree names no one's machine").
