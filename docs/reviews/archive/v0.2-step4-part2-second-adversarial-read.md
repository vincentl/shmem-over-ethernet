## Findings

### S1. Two carriers wait each other out: the carrier rule still judges a peer's abort per wire

**Severity: should-fix** - a rule the code and its model state ("each waiting for the other would
only run both to the bound", `progress-host.c:820-822`; `abort_exit_model.py`'s `no_exclusion`)
broken by two wires a pair: every lead involved ends `OSOE_ABORT_LEAD_WAIT_SECONDS`, 20 s, late,
with a status the specification allows. Rare: two `shmem_global_exit` callers on two nodes within
about a round trip, one node's data wire finishing a segment. Present since 4bc0f1d; 17df5ac's
answer to the first read's N2 made a peer's abort on either wire excuse the other's reset
(`receive_wire`) and left the carrier rule, and the "nobody to tell" rule, per wire.

Location: `progress.c:1951-1968` (`osoe_progress_peers_ended`, each wire's own
`peer_aborted`/`peer_abort_origin`); `:1124-1128` and `:1438-1442` (`flush_aborting`,
`flush_control_aborting`: no abortive goodbye on a wire whose peer's abort has arrived on it);
`progress-host.c:824-830` (the carrier's wait).

Scenario, no helpers: nodes N and X, PEs of N streaming puts to X. A PE of N calls
`shmem_global_exit(5)`; N's word names it, so N's lead carries. N's agent aborts: the pass visits
the control wires first (`progress.c:1768-1780`), so N's abortive goodbye goes on its control wire
to X at once; on the data wire `flush_aborting` first finishes the segment half on the wire
(`:1130-1146`) - a pass later at least, and longer while the socket's buffer is full, though the
abort lifts the unsent limit first (`progress-host.c:798-801`). Meanwhile a PE of X calls
`shmem_global_exit(6)`, declared before N's goodbye is read, so X carries too. X's agent aborts; its
pass receives N's control-wire goodbye before it flushes that wire (one visit, receive then flush) -
`peer_aborted`, nobody to tell - so X sends no abortive goodbye on its control wire; on its data
wire nothing of N's has come, so X's goes there, and reaches N before N's segment has finished: N's
data wire is then `peer_aborted`, nobody to tell, and N never sends its own. Now N waits
(`progress-host.c:828`) for X's control wire, which carried no abort of X's and ends only with X's
process; X waits for N's data wire likewise; each process ends only when its own wait does: both at
the bound. With one wire a pair the same timing cannot do it - whichever goodbye arrived first, its
receiver excludes the sender, ends, and its end of stream releases the other.

Evidence: *run* `carrier-model.out`: `one_wire` holds (69 states); `two_wires` fails, "both
carriers wait for each other" (429 states), trace "0 begins its abort ; 0 sends its abort on C ; 1
reads ABORT on C ; 1 begins its abort ; 1 sends its abort on D ; 0 reads ABORT on D"; `either_wire`
holds (775 states). *Observed in source*: `receive` and `receive_control` hand `receive_wire` the
other wire's `peer_aborted` (`:887-888`, `:899-900`); `osoe_progress_peers_ended` reads only each
wire's own. *Documented*: `abort_exit_model.py` checks two callers on two nodes (`both`) over one
connection and "sends one anyway, a superset of the code's sends" (`:55-56`) - the premise that made
one connection safe, and the one two wires break: with nobody to tell judged per wire, a node can
hear its peer's abort on one wire while the peer hears its own on the other. No test has two
callers on two nodes (the audit control above); `global-exit.sh` would fail such a case, since the
job must end within 6 s of the caller's end (`:28`).

Fix: at no helpers, let `osoe_progress_peers_ended` skip both of a peer's wires once that peer's
abort, naming another rank, has arrived on either - the pointer `receive_wire` already takes - or
record a peer's abort per peer slot rather than per wire, as the first read's N2 put it ("treating a
peer whose abort has arrived on either wire as aborted on both"); and a two-wire case in
`abort_exit_model.py`, with a `two-callers` test whose callers are on two nodes, one streaming.

### N1. The reset's excuse covers one order within a pass; design §6.4 still judges a reset per wire

**Severity: note.** *Observed in source*, the scenario *reasoned*.

`receive_control` judges its wire's end (`progress.c:841-852`) before the pass's data loop has
parsed that peer's data wire (`:1784-1801`). So a peer's abort read on its control wire excuses its
data wire's reset in the same pass - the order the first read's scenario needed, a data wire whose
window filled - but a reset of its control wire reaped in the same pass as its data-wire abort is
not excused: the data connection's `peer_aborted` is still false, and this node ends "the control
wire to node X failed" rather than with the peer's status. The comment says otherwise ("On either of
the peer's wires: its abort read on one excuses the other's reset, reaped in the same pass",
`:845-847`), as does the record's N2 bullet. It needs the peer's control-wire abortive goodbye
unacknowledged past `OSOE_ABORT_GRACE_SECONDS` while its data-wire one went through; a control wire
carries tens of bytes a barrier, so its window does not fill, and only a fault on the control flow's
own path does it, which would most likely drop the reset too.

And the rule is stated only in the code and the record: design §6.4 still says "a reset is judged
per wire, by that wire's goodbye and end of stream" (`shmem-ethernet-design.md:6859`), with no word
of the no-helpers exception.

Fix: word the comment as built (from the next pass either excuses the other; within a pass, the
control wire's excuses the data wire's), and state the rule, and that it holds with no helpers, in
§6.4; or judge every wire's end after both loops have parsed.

### N3. `shmem.barrier-am`'s last quiet does not need the request it says it checks

**Severity: note** (a check satisfiable without the property it names). *Observed in source*, the
mutants' outcomes *reasoned*.

After the barrier every node loops until `osoe_progress_quiet` holds, "the request carried and
answered on a control wire as on a data wire (§3.4)" (`test-barrier-am.c:216-225`), and then closes
(`:232`). A child's quiet holds at once - its ARRIVE was acknowledged by the RELEASE's segment,
whose `ack` was sealed after the ARRIVE was applied - so each child closes, and its goodbye carries
`ack` past the root's RELEASE, which the child applied before its members could leave. The root's
quiet is then satisfied by the goodbyes whether or not any request was carried or answered. So
every mutant of the request path passes this check: `flush_control` without `request_owed`, a
control wire that never asks, `segment_applied` without `owe_ack`, quiet without
`mark_control_busy` (all but the second fail in `control_ack_model.py`, above). Only
`shmem.deadlock`'s declarations catch them - the record lists "a control wire never asking" there
alone - and the barrier test catches only a broken `applied` or `acked`, without which the goodbye's
`ack` is lost too. The first check (`:159-186`, a node idle before its release is not quiet) is
sound: nothing goes back to a child before its RELEASE unless it has asked, and it asks first in
that very call.

Fix: hold every node's close until every node's quiet has held - the arrivals table, outside the
library, as the test's timing check already uses - so that the root's quiet needs its request
answered; or count `transport.am.control_segments_sent` across the loop.

## The properties, one by one

### 1. The control wire's acknowledgement protocol

Held *(run: `control_ack_model.py`, all three configurations)*. Against the data wire's
(`finalize :1070-1111`, `flush :1159-1337`, `busy :1641-1652`, `ack_model.py`): the same rule,
`asks_for_ack` shared (`:1055-1061`), with the detector the only asker, so `wanted` is
`detector_wanted`, never above `last_application_seq`, which every later seal's sequence passes -
a control segment asks only by the late rule, `wanted > acked && flagged < wanted`, and so only
while its sender's own want is unmet (QUIESCES). An answer to a request is a header-only segment
sealed for `owe_ack` (`:1507-1513`) and asks only when its sender has such a want; `flagged` then
passes it, so a pair whose requests cross exchanges at most one answer each (the model's crossings,
and `ack_model.py`'s argument). Nothing stranded: `owe_ack` is set only in `segment_applied`
(`:770-771`), reached only from `receive_control` in the control loop, whose same visit runs
`flush_control` and `settle_control` (`:1774-1777`), and `control_busy` keeps the bit while
`owe_ack` holds (`:1528`); `detector_wanted` rises only in `osoe_progress_quiet`, which sets the bit
with it (`:2040-2042`); `flagged` and `owe_ack` change only in `seal_control`, called only from
`flush_control`, followed by `settle_control` in the loop and in `release_local` (`:1697-1698`);
`acked` only rises, in `segment_applied` (`:772-773`), and a stale bit costs one visit. `acked` is
monotonic on every path; `applied` takes each segment's sequence, which TCP's order makes rising,
and falls once, to the 0 of a peer's abortive goodbye (`:1897-1902`), after which nothing on that
wire is sealed - `complete` has set `peer_aborted` before `segment_applied` runs, and
`flush_control` and `flush_control_aborting` seal nothing then (`:1486-1487`, `:1438-1442`) - as on
a data wire. `request_owed` in `control_busy` is redundant (N2).

### 2. The close and the abort with acknowledgements

Held *(run: the model's LIVE_CLOSE and LIVE_QUIET_EACH)*. The goodbye is sealed on `closing` with
the queue empty (`:1386`), whatever `owe_ack` or a request owed, and carries `ack = applied`
(`:1412`), so it pays the debt and drops the request; it asks nothing. A request arriving after this
side's goodbye sets `owe_ack` with no answer possible and no bit kept (`control_busy` is `c->bytes`
once the goodbye is sealed, `:1526-1527`); its asker needs none, since the goodbye's `ack` already
covers every tree message it sent before this side closed, and it sends none after (the final
barrier). `flush_before_close`'s `osoe_progress_idle` ignores `owe_ack`, as for a data wire. Against
`close_model.py`'s `two_wires`: each wire's goodbye after its own last bytes, the control wire's
after its queue, an acknowledgement owed paid by the goodbye itself, which the model's "may be
dropped after it" allows. No wire is visited for ever: once the goodbye is sent nothing keeps the
bit; before it, `closing` does, until it is sealed. `flush_control_aborting` ignores
acknowledgements, as `flush_aborting` does, and `_aborted`, `_closed` and `_peers_ended` are
unchanged by them. A wire whose peer aborted or reset keeps its bit while closing (`flush_control`
returns at once, `:1486-1487`): visits for nothing, as before.

### 3. The detector, end to end

Held. Safety: a node is quiet only if idle - no control segment queued or on the wire
(`:1839-1843`) - and every control wire not reset has `acked >= last_application_seq`
(`:2035-2044`), where `last_application_seq` is the last segment sealed with an ARRIVE or RELEASE
in it (`:1397-1406`), and `acked` is the peer's `applied`, set after every message of the segment
was applied (`am.c`'s `end_segment`, `progress.c:769`): deadlock.h's step "a message in flight at t*
... was acknowledged by then - applied" holds for the tree's messages again *(run: the model's
SAFETY, and `deadlock_model.py`'s `control_wire` failing)*. The detector's messages are excluded on
both sides: not counted into `last_application_seq` (`:1398`) nor into `application_applied`
(`:574`); header-only requests and answers move no activity. Liveness in a real deadlock: every
agent runs, so a request is sealed when its wire's segment completes and answered in the visit that
reads it *(run: LIVE_QUIET, LIVE_QUIET_EACH)*; a reset wire is skipped as a data wire is (`:2037`),
and a receive error there is a fatal unless the node is aborting; a peer that has sealed its goodbye
has passed the final barrier, which no deadlocked job's nodes do, and its goodbye answers anyway;
crossing requests settle in one answer each. `deadlock_model.py`'s `control_wire_acked` is a
faithful abstraction of the safety argument and of no more (N2): it is the design's barrier case
with the post renamed; the RELEASE, an application message the other way, is the same kind of
message and needs no case of its own. The F1 scenario: node 9's ARRIVE and its request ride the same
blackholed flow, so node 9 is not quiet until the path recovers.

### 4. The pass's new order

Held. No data message's handling enqueues a control message: the host callbacks a data message
reaches - `notify`, `completed`, `landed`, `abort_arrived` (a declaration, `progress-host.c:302-307`)
- queue nothing, and `deadlock_arrived` is reached only by a DEADLOCK message, which `check_plane`
confines to the control wire. Every control enqueue made during the pass marks its bit; one for a
slot the loop has passed is visited at the next pass, which follows at once since its cause moved
(a receive) - unchanged by the order; a RELEASE is sealed by the end-of-pass `release_local`, which
runs after both loops as before. `release_local`'s two calls each flush and settle only control
wires; a second `flush_control` on a slot in one pass offers the send in flight and returns
(`wire.c:265-277`). The readable takes clear exactly their own ranges (`ring.c:322-337`), so taking
the control range first changes no bit the data take sees. The abort and the end-of-pass submit are
order-free.

### 5. A peer's abort on either wire excusing the other

Held for what it excuses: `peer_aborted` is set only by an OSOE_AM_ABORT on that wire, so the peer is
ending whatever origin its abort names, and a "genuine failure" of its other wire is the reset its
end makes; the excuse marks that wire `abort_done` (`:850`), nobody to tell. It is limited to no
helpers by the pointers (`:887-888`, `:899-900`), stated in the comments and the record, not in
§6.4 (N1). Not held for what it left out: the carrier rule (S1), and one order within a pass (N1).

### 6. `enqueue_control` after a goodbye

Held. A control wire's goodbye is sealed only while closing (`:1386`), and `osoe_progress_close`
follows `flush_before_close`, whose idle needs no team's release pending (`:1817-1818`) and every
control queue empty, after the final barrier. An interior node's RELEASE to a child is queued before
its own local release, which waits for it to be sealed (`releases_queued`, `:1700-1703`), so the
goodbye toward that child can come only after it; a team's barrier precedes the final barrier on
every member, and its forwards leave before its members do; a node never receives a tree message for
a team it is not in. Only a detector message can come late - a DECLARED, or a veto - and it is
dropped (`:320-325`); a probe during the close sets `answering` with no tick to answer it.

### 7. The zero-copy budget

Held *(run: `zero-copy-limit.out`)*: `buffers + 2 × 2(n - 1) + 16 × (n - 1) + 1` passes 65,536 at
3,275 nodes, so 3,274 (65,525 completions) as the README and §3.3 say; 3,638 on one wire a pair;
1,819 at 3d30d1c. A control wire cannot lend whatever `attach_purpose` sets: every send of it goes
through `osoe_wire_send`, which copies (`wire.c:314-317`, `:293`), so `w->zero_copy = false`
(`:162-163`) is a second guard. `lending` is `osoe_owner_wires(o, …)`, exactly ring o's data wires
(`owner-map.h`), and the bound is a count over the ring, not over indices. The fatal now names the
data wires it counts; at a helper count it says "peer nodes' data wires" of a helper's share, which
is accurate.

### 8. `check_plane` before `destination()`

Held. Before `destination()` the parser checks only framing - the segment's length and count, the
kind's range, the message's length against its fixed part and the segment, a payload only for kinds
that carry one (`am.c:151-231`) - and touches no heap; a header-only segment's `ack` and flags are
legitimate on either wire. `destination()` is reached only for a payload (`am.c:245-246`) and asks
