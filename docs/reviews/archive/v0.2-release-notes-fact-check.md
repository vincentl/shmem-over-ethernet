# Fact-check of the 0.2.0 release-note draft

The draft: `docs/release-notes/0.2.0.md` (172 lines) and the section "For the 0.2 tag" in
`docs/release-checklist.md` (lines 110-144), both in the worktree
`build/scratch/wt/release-notes-0.2`, commit `d3355b2` on `7a42c92`. Read-only: nothing in the
repository was changed; the only file written is this one (plus scratch copies outside the tree).

**Trees read.** The draft's base is `7a42c92`. `main` moved twice while this was done: `489685e`
(the single-node build's fix) and now `29d3e01` (keepalive off on loopback merged at 19:23). The
branches the draft leans on were rewritten from WIP commits to final ones at 19:25-19:27 while the
check ran, so I read the final records: `blocking-gets` `0175253`, `zero-copy-memlock` `99f055d`
(stacked on `blocking-gets`), `fast-link-kit` `a674343`. "README" below is `README.md` at `29d3e01`
unless it says `@v0.1.0` (then `git show v0.1.0:README.md`). Decisions and reviews are cited by path
and line at `29d3e01`; `docs/pi-cluster-results.md` is "PCR" (unchanged since `7a42c92`).

**Verdicts.** TRUE (source given) / OVERSTATED (stronger than its source) / WRONG / UNSUPPORTED (no
source found) / STALE (true at `7a42c92`, moved since) / NIT.

**Not checkable here.** No Linux build or `nm` (the Lima VM is off limits), so "the library exports
the same names" rests on identical headers, no changed definitions in `git diff`, and the records'
count of 3,595 names at both releases. The Pi numbers are read from the records and the evidence
files, not rerun.

### Lines 66-67 (mixed versions)

- **"Nodes of 0.1.0 and 0.2 do not form one job: their connections' hello and their shared memory's
  layouts differ"** - TRUE of the facts. Hello version 3 at `v0.1.0:shmem/src/listener.c:44`, 4 at

  versions?", `node.c:1138-1143`); no layout crosses between nodes.
- **"and each refuses the other"** - WRONG as to the mechanism. A listener that sees a hello of
  another version does not answer or refuse: `caller_answer` ends `caller_drop(c); /* a stranger */`

  candidate port" and retries (`listener.c:687-720`, `833-880`); the only trace is the 30-second
  notice "shmem_init on node N has waited S s for node M ... to answer ... no answer to the hello"
  (`listener.c:636-655`), and the start waits for the launcher's timeout or
  `OSOE_NO_PROGRESS_TIMEOUT` (default never). So the job cannot form, but nothing refuses by name
  and nothing names a version. The README says nothing about mixing releases (it asks only that
  the install be the same on every node, README:358-360).
