# Adversarial read: v0.2 step 2, the tree's shape from the link (the merge point's)

A fresh agent's read of `main...shape-data-path`, both parts with Part 2 the
focus, run on 2026-10-07 from `f7745a0` while the branch moved to `3ef3ba3`
(its VM runs on `7dbf522`, release unless stated, under the lock;
`internode-generic.c` byte-identical at `7dbf522` and `3ef3ba3`), asked to find
two nodes building different trees for one call, a per-call fan-out confusing
the counters, grants or lanes, an exception taking the per-call shape, or a test
that could not fail. The report follows as it was handed back; what was done
with each finding is in `docs/decisions/2026-10-07-shape-data-path.md`, "The
adversarial read".

**Verdict:** the rule holds. For the same call every node computes the same
shape, and no shape is larger than the layout; no defect on the data path. The
mechanism's own tests are weaker than the mechanism: if the data path ignores
the shape, no test notices; if the grants go to another tree than the data path
uses, no existing test notices. Two smaller things to fix before the merge:
`SHMEM_INFO`'s text is false, and the decisions index is stale.
