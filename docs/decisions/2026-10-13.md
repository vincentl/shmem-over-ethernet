liburing 2.9 built by the environment's setup script (the brief's appendix). It
runs the full build whole: the probe passes every line, the release build has
no warning, tier 1 and tier 2 pass - 449 internode tests among them, over
loopback with io_uring and futex2 - and the model suite runs one model at a
time, in 2 h 35 min. Root there cannot raise `ulimit -l` (8192 KiB), but holds
`CAP_IPC_LOCK`, so only the two tests that lower the limit to see a refusal
skip, by name. Tier 3 needs `ethtool`, which the setup script can add. So a
second session there can take C items with tests in the full build.

- **B4**: the cache routines stay in `shmem.h`, where the programs that call them

  author's to confirm; the lead recommends keeping them.
- **P12**: the 32-bit atomics asserted too, not only the 64-bit ones the item
  named - the futex words and the node's 32-bit protocol words are shared the
  same way. The lead agrees.

  though §4.9 changed long ago.

  (merged here); the others say what a run measured when the suite had 871 tests
  and stay as measured.
- Several models' docstrings name a property other than the one a breakage fails.

  so a lost wake shows as STUCK whenever a blocked thread comes first.

- Unverified here: B6's cross build in the review's direction (x86-64 built on
