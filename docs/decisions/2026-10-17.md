## The PASS expressions

A test property is a CMake list, so a `;` in a quoted expression splits it in two and ctest
passes the test on either half. Audited as ctest holds the tests - `ctest --show-only=json-v1`
of the release, tier 3, single-node, asan and tsan builds - and by a scan of the CMake sources,
which agreed: five properties were lists. Two are FAIL lists, alternatives by intent (a
launcher's ways of failing). Three were PASS expressions split by accident:
`shmem.typed-rma.ibput-misuse`, one of whose halves was " spec", which nearly any output holds;
`shmem.alltoall.stride`; and `shmem.team-split.stale-handle.L2`. Each is written with `.` where
the `;` was, as batch 2 wrote its three, and each message holds the whole sentence
(`rma-typed.c`, `collectives.c`, `active-set.c`, `team.c`).

So that a fourth does not pass unseen, **`shmem.pass-expressions`** (`cmake/CheckPassExpressions.cmake`,
tier 1, in every build) reads the build's tests through ctest's own JSON and fails on any PASS
or SKIP expression held as a list, which finds a `;` arriving in a variable as well as one written
out; FAIL lists are left alone. Against the tree before the fix it named the three, among 452
expressions, in about 6 s. The kit's static step (`docs/fast-link/verify.sh`) gains it, and
`settings-known`, which batch 1 added and the kit's expression lacked. Not covered: a refusal
test's PATTERNS (`refusal.sh`), which a `;` splits too, but into parts each of which is required
(batch 2's note), so a split there loses only the parts' adjacency.

## D8, each owner's last pass with its age

Layout 40: `transport.am.last_pass_ns` appended to each owner record (`struct
osoe_am_owner_metrics`), the instant the owner's pass ended (`osoe_progress_poll`), stored with
release order beside the passes counter - §3.16's single-writer publication. The clock is
`CLOCK_MONOTONIC_COARSE`, the last tick's `CLOCK_MONOTONIC`, which the vDSO reads without the
counter: **2.5 ns a read** in the `osoe` VM against 14.1 ns for `CLOCK_MONOTONIC` (20 million
reads, three rounds alike), and an instant never ahead of the fine clock, so the age `osoe-stat`
computes from its own `CLOCK_MONOTONIC` is at most a tick too long. The metric table names it a
state in `ns`, an instant, as `pe.blocked.since_ns` is.

`osoe-stat`'s owner table gains a `last pass` column: the age, or `-` for an owner that has not
passed, a segment from before layout 40, or an instant ahead of the reader's clock (a time
namespace's). `OSOE_SEGMENT_NEWEST_LAYOUT` is 40: until it was, `shmem.stat.L2`, `L4` and
`shmem.stat.link` failed, the tool calling the watch word's encoding unknown at a layout newer
than itself - its guard doing its work. Tests: the fake segment's owner views (`stat.segment`):
the header, the agent's age in seconds, `-` for a helper that has not passed and for one ahead of
the clock, and the dump's raw instant; and `shmem.stat.view.last-pass` (internode, in every
preset): node 1's only PE stopped by SIGSTOP for two seconds, its agent's last pass read **2.075 s**
old and the running node's 0.065 s. A live table showed the idle agent's last pass 13.4 ms ago.
The README's hang paragraph says one look now tells the stuck owner, where it took two; the
design note's owner records say so too.
