# The night of 2026-09-26: the stress tester decided

The author asked for a stress tester and benchmark for the finished 1.6
implementation: all-to-all, teams, a streaming large-memory bucket sort, a
stream of progress, and `parallel_print`, a team collective that hashes each
PE's formatted text and prints each distinct text once under a Slurm-style
range of the PEs that produced it. A proposal was written
(`docs/design/osoe-pacer-proposal.md`) and the author decided its open
points the same night. This is the record; the first brief is
`docs/prompts/task-stress-phase1.md`.

## 1. The tool is `osoe-pacer`, in `tools/pacer/` (Claude, from the author's two names)

The author did not want `stress` in the name and offered `osoe-mark` and
`osoe-pacer`. `pacer` was taken: it is a word on its own - the tool paces the
library - where `mark` is a piece of "benchmark", which CLAUDE.md's naming
rule refuses. The place, `tools/`, beside `osoe-bench`, was the author's. Not
installed until phase 4 decides. *Undo*: rename the directory, the target
and the proposal; nothing else refers to the name yet.

## 2. `parallel_print`'s labels (the author)

World PE numbers in Slurm's bracket syntax, `[0-3,8-11]`, whatever team the
call is on; **a call on any team but the world carries the team's name
before the bracket**, `even[0,2,4,6]`, `shared[4-7]` - the author's
amendment to the proposal, which had left the team out. Node folding
(`pi-[001-004]`) later, as an option. *Undo*: the label function alone.

## 3. `parallel_print` stays in the tool (the author)

Not a `shmemx_` extension; `shmemx.h` stays empty by design (§7.4). Written
against the OpenSHMEM API alone, so it compiles against SOS too, which tells
a tool failure from a library failure.

## 4. Phase order as proposed (the author)

Running first; threads second, because the lock-free shared-context path is
the newest code and holds the one open item; the rest of the surface third;
the mixer and soak fourth. One small move, Claude's: the failure lines
through `parallel_print` and `--stop-on-failure` go in phase 1 rather than 2,
since phase 1 builds `parallel_print` and the planted-defect tests want a
readable failure. *Undo*: leave them for phase 2's brief.

## 5. The memory budget (the author)

Default half the heap; `--memory` to go higher, as a size (`1g`) or a share
(`90%`), refused with the `SHMEM_SYMMETRIC_SIZE` to set when the heap cannot
hold it. So pushing higher is one variable and one option.

## 6. Smoke tests in every preset: pending

The author asked for more explanation before deciding. It is in the
proposal's §3, "Tests": five things - quick runs, the four node maps, each
sanitizer, the plant tests that prove each oracle fires, the print test that
pins the format - for about a minute a preset in release and two or three
under asan and debug; what they buy is that the tool cannot rot, and what
they do not buy is stress, which comes from the runbook and the soak. The
brief registers them in one block with a comment; the author decides once
he has seen their real cost.

## 7. The briefs are `task-stress-phaseN.md` (the author)

The phases are not slices of a §7.1 step; `docs/prompts/README.md` says so.

## Flagged, not decided: team numbers are a per-job budget

A destroyed team's number is never given back (`team.c`; design §5.7, the
author's 2026-09-25 decision), so at the default of 64 with three predefined
a job can create 61 teams in its lifetime, and a split past that returns
nonzero on every PE of the parent, not fatal. The teams exercise is shaped
around it (proposal §4.3). An application that makes a sub-team per
iteration stops at 61 iterations; whether that is acceptable for the release
is a question for the author, raised again by phase 2 once the exercise
makes the cost vivid.
