## Proposed to the author: the repository for a stranger

The author asked for the repository's organization - its directories, names
and root README - to be looked at again with a stranger in mind, and for any
change needed to make it understandable, approachable and usable. Proposed,
awaiting the author's word:

1. **Say how osoe was built.** The README never says that osoe was developed
   with AI assistance, and a reader meets `CLAUDE.md` at the top of the tree,
   `docs/prompts/` and 551 co-authored commits with nothing to explain them. A
   short section - who directed and who wrote, the briefs, the adversarial
   reviews and their refutations, the records, the commit lines - with
   pointers to each.
2. **A quick start near the top**: the packages, the build, and the ring
   example on one machine with `osoe-launch`, in five commands. Today a newcomer
   reaches "Running a program on one machine" some 300 lines in.
3. **A table of the repository's layout** in the README: `base/`, `shmem/`,
   `tools/` (each directory with the program it installs), `cmake/`, `dev/`,
   `docs/`.
4. **`docs/README.md` rewritten for a newcomer.** It opens today with "Start with
   the decisions index", which is the project's own way in. Three parts
   instead: using osoe, how it works, and the record of how it was built - the
   893 files of raw evidence named as such.
5. **A paragraph of README** in `base/`, `shmem/`, `tools/`, `dev/`,
   `docs/design/` and `docs/reviews/`; only `tools/modelcheck/` has one now.
6. **Nothing moved and nothing renamed.** File names are consistent - kebab
   case throughout, capitals only in raw evidence and CMake's own modules - and
   every path is cited across the records and the history. The README stays
   long, since the author chose to have it state every limit.

Two choices outside the tree: the public repository's name (`osoe`, as the
library, the tools and the README title, or `shmem-over-ethernet`), and
continuous integration on a public host, after the release.
